# Лабораторная работа 4

Алгоритмы отсечения отрезков и многоугольников. Основной вариант **14**: Лианг–Барски в первой части, Кирус–Бек во второй.

Выполнил Шумиляк Александр, группа 2, подгруппа 1.

## Запуск

Откройте **Лабораторная-4.html** двойным щелчком. Приложение автономно: сеть, сервер и установка зависимостей не нужны.

Модульная версия для разработки: `node server.mjs`, затем http://localhost:5173. Требуется Node.js 20.11 или новее. Если порт занят: `PORT=5174 node server.mjs`.

## Работа с приложением

1. Выберите часть работы. Для варианта 14 алгоритмы выбираются автоматически.
2. Отредактируйте данные или откройте пример из каталога `examples`.
3. Нажмите «Выполнить отсечение». Синее — окно, серое — исходная геометрия, розовое — видимые части.
4. Выберите отрезок, затем исследуйте шаги: кнопки перехода, ползунок, воспроизведение и таблица. Оранжевый показывает состояние выбранного шага; итог остаётся розовым.
5. Колесо меняет масштаб, перетаскивание сдвигает плоскость. Кнопка «Вписать» возвращает весь набор в кадр. Опция «Добавлять отрезки» позволяет задавать концы двумя щелчками.
6. Сохраните изображение PNG, входные данные или полный результат JSON.

Раздел «Кирус–Бек · W и D» содержит интерактивную геометрию, движение P(t), нормаль выбранной стороны, W, D, параметр пересечения и таблицу интервалов.

## Форматы данных

TXT точно соответствует заданию:

```text
n
x1 y1 x2 y2
... n отрезков ...
xmin ymin xmax ymax
```

Дробные числа пишутся с точкой. Пример: `examples/rectangle.txt`. Окно невырожденное: xmin < xmax, ymin < ymax. Разрешены 0–1000 отрезков, координаты по модулю не больше 10^6. Строки с комментариями после `#` допустимы.

В части 2 строка прямоугольника из TXT сохраняет формат, но **не участвует в отсечении**. Фактическое окно задаётся списком вершин, по одной паре x y на строку. Вершины перечисляются последовательно по контуру в любом направлении. Окно должно быть выпуклым, без повторов и самопересечений, от 3 до 100 вершин.

JSON сохраняет весь набор. Поля: `variant`, `part`, `algorithm`, `segments` (массив пар точек), `rect` (xmin, ymin, xmax, ymax), `clip` (вершины окна), `subject` (вершины отсекаемого многоугольника). Пример: `examples/convex-window.json`. Ключи алгоритмов: liang, cohen, midpoint, cyrus, polygon. Сохранённый результат тоже можно открыть как вход: поле results будет пересчитано.

## Численные особенности

Граница включена. Точные методы здесь означают вычисление пересечений по формулам, а не рациональную арифметику: используется JavaScript Number. Вывод округляется до 6 знаков; JSON сохраняет полученные числа без дополнительного округления. Почти параллельные линии и почти совпадающие пересечения чувствительны к численным погрешностям.

Метод средней точки приближённый: длина неразрешённого граничного фрагмента не превосходит ε (по умолчанию 10^-7), координаты результата прижимаются к окну. Промах ближе ε и касание могут быть численно неразличимы. Этот метод не входит в основной вариант 14.

Проверка выпуклости окна выполняется за O(m²); собственно Кирус–Бек — O(m) на отрезок. Трассировка занимает память пропорционально числу шагов. В режиме многоугольников результат пересечения может выродиться в отрезок или точку: такие результаты сохраняются и рисуются.
